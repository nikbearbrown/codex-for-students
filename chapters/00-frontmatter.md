Codex is an agentic system. You give it a task. It plans the work, writes files, runs commands, iterates against tests. The autonomy is the feature. It is also the reason the discipline of using it well has to be deliberately built, because the *default* path with an agentic tool is to let the agent decide, and the default path is exactly the path that produces excellent output and an atrophying practitioner.

This book exists because that pattern came home from AP Computer Science one afternoon, in the voice of my son.

He had watched a friend ace a problem set — trace a Godot-style signal handler by hand — by pasting the assignment into Codex and accepting whatever came back. Two weeks later the laptops closed for a quiz with a variant of the same problem and the friend froze. Seth had used Codex on the same homework. He had spent more time on it, not less — predicting which subscriber would fire before reading Codex's response, running intermediate prints to watch the signal flow resolve, modifying one connection to see what would change. He passed the quiz. Six weeks later they were two different practitioners.

I teach AI engineering at Northeastern University, where I have spent the last decade watching graduate students, engineers, and researchers adapt to one wave of capability after another. The pattern Seth described in AP CS is the same pattern that shows up in graduate seminars and at companies adopting agentic coding tools. It has a name now — the *homework/quiz gap*, when the AI substitutes for the cognitive work the homework was meant to develop. The 2025 Bastani randomized controlled trial measured it at seventeen percentage points on the unassisted exam. The Kosmyna EEG study measured brain connectivity dropping by up to 55% during AI-assisted writing. The Anthropic 2026 coding-skills study found the same shape in software engineers learning a new Python library. The structure is replicable. The cost is hidden under fluent output.

That is the gap this book fills. Codex has excellent official documentation. There are good developer-focused courses from Vanderbilt and Coursera. There is, as far as I can tell, no book yet that takes Codex's agentic surface — the Ask Mode → Code Mode gate, AGENTS.md, the autonomy — and teaches a student how to *conduct* the system rather than be steered by it. This is that book.

A note on voice. The book is co-written. My son **Seth Brown** is the co-author. Seth is a high-school senior in Troy, Missouri, and a self-taught game developer across five engines. He has shipped *Haunt & Harvest*, a co-op horror survival game in Godot 4 migrated system-by-system from Unreal Engine; *Midnight Fuel*, a Roblox/Luau horror game with cinematic intro and modular networked architecture; and *Bubble Pop*, a Google Play mobile arcade title with full AdMob integration. He runs *Zebonastic*, a Next.js platform where he publishes weekly on horror game psychology.

The deeper credential is operational. Seth and I co-built two production AI agents that operationalize the discipline this book teaches — *Walker*, a Unity refactoring conductor that enforces a five-phase audit-restructure-CLAUDE.md-refactor-verify model and names the five supervisory capacities by initial; and *Zelda*, a senior game-design-documentation consultant with a 34-command library, a phase-gate enforcement layer, and a seven-failure-mode audit pass. Both are public at [humanitarians.ai/tools](https://www.humanitarians.ai/tools/). Codex's Ask Mode → Code Mode gate, AGENTS.md, the five supervisory capacities — the operational machinery this book teaches — show up in Walker and Zelda as deployable form. The books teach the abstraction; the agents are the worked artifacts that prove the abstraction holds up under production pressure.

The narrative chapters are written in Seth's voice. The framework chapters are mine. The voice shifts on purpose. A discipline written only by an adult about how students should behave has one shape. A discipline worked out by a practitioner inside the constraints students actually face — deadlines, partial knowledge, a teacher still calibrating to AI, classmates burning capability for grades — has a different shape, and a different authority.

The book does not cover Codex's full API surface, the deep internals of the underlying model, or every shipping change in the agent layer. It does not argue whether students should use AI; they will, the question is how. It does not pretend the discipline is finished; the closing chapters say exactly what would change our minds.

If you are a student opening this book, you do not need to take its claims on faith. Try the discipline on one build. Compare what you can do, without the tool, a month later — to the version of yourself who would have produced the same artifact with no discipline at all. The difference is what the book is for.
